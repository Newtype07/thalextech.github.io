# Target

A separate BTC target-to-trade app. Drag the horizontal target line or its price label to choose a USD target, and select one listed expiry; the app selects calls at or above spot and puts below spot. It automatically compares singles with all same-expiry 1:1 vertical debit spreads, maximizing `(target − strike) / ask premium` for calls or `(strike − target) / ask premium` for puts. For a spread, payout is long intrinsic minus short intrinsic and entry cost is long ask minus short bid. Both legs must have executable size, and the net debit must be positive. Exact ties retain the single. Both sides are loaded together so crossing spot switches instantly. Payout is gross, not profit. Required hit rate is `1 / multiple`; BUY requires historical expiry frequency strictly above it. MAYBE means expiry frequency is strictly below it but touch frequency is strictly above it; this flags an early-exit case without valuing that exit. Otherwise PASS.

The default expiry is the future listed last-Friday-of-the-month maturity closest to 30 days from the snapshot, with earlier expiries winning exact ties. If no monthly expiry is listed, it uses the future listed expiry closest to 30 days. Refreshes retain the selected expiry while it remains listed.

`npm ci`, then `npm run dev`. `npm test` checks the rule and historical sampling; `npm run build` prepares observed history and builds the static app. Set `VITE_BASE_PATH=/target/` for the repository deployment. The homepage discovers `index.yml`, and `build_apps.sh` discovers the app automatically.

`src/target-trade.js` owns ranking, hourly historical comparisons and daily candle aggregation. `src/market-data.js` translates public Thalex instrument, index and ticker responses into options and executable USD ask premiums through the shared rate-limited client. `CandleChart.vue` renders the history and target; `App.vue` coordinates inputs and loading. The header’s Trade on Thalex link uses the same options strategy-builder URL as Combo, preselecting BTCUSD, the selected UTC expiry date and the winning buy leg (+1), plus the sell leg (−1) for a vertical. It updates with the current trade and disappears when no fresh eligible trade exists. There are no trading/order endpoints.

History is generated at build/dev time from tracked `apps/backtest/source-data/thalex/BTCUSD_index_1h_*.parquet`. The browser receives a compact OHLC JSON file, not Parquet. Each market refresh fills the gap from the archive through the latest completed hourly bars using the public API. Current-hour minute OHLC plus a subsequent index snapshot form the in-progress candle; its close is exactly the spot label. Only completed hourly bars enter the historical frequency sample. Missing hourly observations invalidate windows; history is never interpolated. The snapshot-to-expiry horizon is rounded to the nearest hour (minimum one hour) and shown in the app. Windows overlap and compare terminal percentage returns, not intraperiod touches. Negative target moves count downward returns. The chart uses 4-hour candles for 30D, daily candles for 90D/180D, 3-day candles for 1Y, and Monday-aligned UTC weekly candles for 2Y, aggregated from the same observed hourly prices; the candle interval label is a borderless dropdown offering 1h, 4h, 12h, daily, 3-day and weekly. An explicit interval choice persists across range changes. Neither range nor interval changes the verdict sample.

Only positive asks with available size and a mark timestamp within two minutes are considered. Failed, missing, empty-book or stale quotes are counted as excluded. The selected strike is therefore the best among available executable quotes, not unquoted strikes. Snapshots refresh automatically every minute and on return to the tab. A replacement spot and chain are committed together; fresh results remain visible during refresh. A failed refresh retains the last snapshot, but any quote or snapshot older than two minutes is suppressed until reconnection. Changing expiry aborts obsolete requests. Historical touch % counts the same valid windows whose subsequent hourly high (upside) or low (downside) reaches the target percentage move. The entry candle is excluded to avoid counting touches before entry. A target at spot is already touched. Touch % can produce MAYBE, but never BUY by itself: an early exit has not been valued. Ties pass. Missing data shows an unavailable verdict.

This implements the requested rule rather than a full expected-value calculation: outcomes below the target, fees, settlement basis and slippage are not modeled. The target line and its price label update while dragging, as do the trade and verdict. The chart fits visible candle highs and lows with 5% range padding on each side. A small fallback keeps flat-price windows usable. Target, strike and spot do not stretch the domain; out-of-view references are labelled at the edge with an arrow. The chart scale stays fixed while repricing. The target snaps to positive multiples of $5 when dragged. It also supports arrow keys ($5 increments; Shift for $100) and Home/End for the visible price bounds.

Public API references: https://thalex.com/historical-data and https://thalex.com/docs/ .

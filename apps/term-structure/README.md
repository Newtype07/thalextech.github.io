# Term structure

BTC / ETH volatility by live listed expiry. Explore historical dot clouds, compare against matched-window realized volatility, and export the chart as a high-resolution PNG.

```sh
npm ci
npm run dev
npm test
VITE_BASE_PATH=/term-structure/ npm run build
```

`dev` and `build` first run `build:data`, which reads the canonical Parquet files in `../backtest/source-data/thalex`. To regenerate the cache independently, run `npm run build:data`. The root app build discovers this app automatically; `index.yml` registers the home catalogue entry. No API keys or backend are needed. `VITE_THALEX_API_BASE` optionally overrides the public REST base. `VITE_THALEX_WS_URL` overrides the WebSocket endpoint; a custom non-Thalex REST base uses REST only unless an explicit WebSocket URL is supplied.

## Chart and settings

The compact top bar, typography, controls and shared `StyledSelectMenu` follow Straddle. The **Volatility** dropdown switches between **Expiry IV** (default) and **Forward vol** without making data requests. The top-bar **Scatter / Lines** buttons select separate chart presentations. Scatter shows historical dot clouds and the current white curve, with live marks/book fallback, delta slices and percentiles. Lines shows historical IV (or forward-volatility) snapshot curves with RV context; scatter dots, snapshot point markers and the extra live curve are absent. Axes fit the visible curves. The current-source control appears only in Scatter mode.

In Lines mode, the **Resolution** dropdown sits beside the style buttons: **Daily** selects 24 hourly closes, **Weekly** selects seven closes one day apart, and **Monthly** selects four closes one week apart. The newest target is the latest completed UTC hour at the refresh reference time, followed by 23 hours, six days, or three weeks backwards respectively. Lines reuse already interpolated history without API calls. Missing hours are omitted; no neighbouring timestamps are substituted. IV curves connect the available maturities while hover details identify missing values, without inventing an IV observation at the skipped expiry. A snapshot containing just one observation uses a short horizontal stroke so its value stays visible. Forward-volatility curves retain missing interval gaps. Older curves are dimmer, and hovering a curve shows its UTC timestamp and maturity values. The subtitle tooltip reports available versus requested snapshots. Switching back to Scatter restores its cached dot cloud. The round chart-settings button controls **Realized volatility** in either presentation; RV is dashed with hollow markers.

PNG exports include the selected chart presentation, title, subtitles, axes, plotted curves and RV context. Filenames identify Scatter or the Lines resolution. Coverage annotations, tooltips, controls and detail tables are excluded. Source details appear only when hovering over either chart subtitle, with a dark background and readable text. The tooltip contains only **IV data** and **RV data**, each with its overall loaded date range and a one-line source description. It has no expiry breakdown, formulas, row counts or fetch logs. IV covers all loaded historical IV observations; RV covers all loaded valid, completed index OHLC bars, independent of the selected snapshot resolution or RV visibility. Expiry details stay collapsed below the chart; source panels and footnotes do not occupy the layout.

## Single-path position simulation

The **Simulate** tab reuses the same `PositionBuilder` as Payoff and Combo P&L. It starts with a **short ATM straddle**: sell one call and one put at the nearest paired strike, in the listed expiry closest to 30 days. Opening the tab runs automatically once live spot, listed instruments and **ATM mark** IVs are ready, without waiting for historical data. Add or remove legs (up to four), toggle buy/sell and call/put, and choose quantity, expiry and strike separately for each leg. This supports single options, verticals, ratios and calendars. Builder marks and Greeks use the same zero-rate ATM-curve model as the simulation, rather than individual strike quotes.

Each run hedges the **aggregate live-option delta** along one common spot path. The always-visible **Simulate until: First expiry / Last expiry** toggle sits beside the simulation controls, defaulting to **First expiry**, and remains available while legs are edited or cannot be valued. Switching it reruns automatically and preserves the selected legs. At **First expiry**, expiring legs cash-settle at intrinsic, later-dated legs close at their rolled model marks, and the hedge unwinds. At **Last expiry**, each earlier leg cash-settles at its own exact expiry, its payout stays fixed, and its delta is removed; the existing hedge policy continues on the remaining legs until the last expiry, when the hedge unwinds. The path clock includes every option expiry even when it falls between regular steps. For a call calendar, sell the near call and buy the far call at the desired strike. The selected exit is reflected in the trade facts, chart labels, run duration and CSV, and explained in Hedge settings. For positions with a single shared expiry, both choices end at that same expiry.

The captured ATM curve is independent of the chart's IV slice or forward-volatility view. The **realized / forward volatility** slider ranges from **0.50× to 2.00×**, and annual drift defaults to zero. **Refresh** captures fresh market inputs and generates another run while preserving the selected legs; unavailable or expired selections require correction. Without live data the simulator waits. Hedge settings appear in a compact right-hand column by default, with a hide/show control; on smaller screens they sit above the charts. Every valid leg or settings change automatically reruns after a brief pause to combine edits. Invalid settings retain the last valid result with an inline error.

- **Path:** the simulation step is fixed at **1 minute**, with no step selector. Exact expiry and variance boundaries are included between minute observations when necessary. Interpolate total variance `W(t) = IV(t)^2 * t` linearly. Its slopes supply piecewise-constant forward variance. Each price increment uses the exact integrated variance over that step, scaled by the square of the selected realized/forward-IV ratio. Annual drift is editable and defaults to 0%. It is the geometric-Brownian expected-price growth rate, entered as an annual percentage; the log-return drift includes the usual minus-half-variance term. Negative forward variance and extrapolation beyond the curve are rejected.
- **Marks:** hold the starting forward curve fixed in calendar time. Each leg's remaining variance is `W(T_leg) - W(t)`, so different expiries roll independently. Legs with the same expiry share IV; there is no strike smile or stochastic volatility model.
- **Hedges:** initial delta is flattened immediately. A breach timer requires delta to remain outside the threshold for the full period; returning inside resets it. Alternatively, fixed scheduled checks hedge only when outside the threshold. Tolerance overrides either policy at the next observed simulation step; zero disables it. All bands are absolute BTC/ETH delta and hedges return net delta to zero. Scheduled periods must be whole minutes.
- **P&L:** exact option revaluation plus the linear hedge ledger less configurable execution costs. Attribution separates time decay, term roll, delta, gamma, higher-order/cross effects, hedge trading and costs. Time and roll are revalued in that order; delta and gamma use previous-step Greeks, with a residual reconciling them to the exact spot revaluation. Every row reconciles to net P&L.
- **Performance:** the USD P&L chart comes first, with the index-price chart below it, on a pure black background. There is no KPI strip above the charts; net option, hedge and total P&L remain visible in the compact chart legend and update during inspection. Charts have no grid lines, the index path is a thin white line, and all three P&L curves use step-after rendering, holding each observation until the next simulation timestamp. The cumulative total P&L copies Combo P&L’s green/red mark-curve palette, 1.5px stroke and three-stop gradients (0.42 / 0.22 / 0.06 opacity fading toward zero). Option P&L is white and hedge P&L grey, with thin solid strokes. Colour is confined to curves, swatches and inspection markers; monetary values in the legends are white and rounded to whole dollars. CSV values retain full precision. Combo-row totals are bold, and a full-width divider separates the leg builder from the simulation controls. The refresh icon has a wide click target and regenerates the path; controls stay compact and export sits above the charts. Every executed hedge is marked on the index path: green for buys, red for sells, including the initial hedge and final unwind. Hover details identify side, quantity, trigger, day and fill price. Both charts share the same horizontal scale and inspection time. The first chart shows option, hedge and total P&L; the index and hedge fills follow below. Each component includes its own execution costs, so option plus hedge equals total at every point. Hover shows the most recent observation at or before the pointer, matching the step intervals, and arrow keys move between observations; leaving the chart restores expiry values. The performance CSV exports the same net components. Hedge and execution controls sit in the collapsible settings column; the shared leg builder shows entry marks and Greeks, while the performance view focuses on index and P&L.
- **Fresh paths:** every automatic run, page refresh and the **Refresh simulation** icon uses fresh random draws. Settings changes update the simulation automatically; the **Refresh simulation** icon generates another path with the current assumptions. Returning to the tab preserves the existing result.

Pricing reuses `lib/thalex.js` (zero rates/carry, 365.25-day year). Execution uses spot fills with editable all-in costs in bps of underlying notional. Option costs apply to each leg’s absolute quantity on entry and to any unexpired legs closed at the selected exit; expiring legs settle at intrinsic without a modelled settlement fee. Every hedge, including opening and unwinding, incurs its configured cost. Funding, basis, margin, liquidation, jumps and price moves between observations are outside the model. Runs are limited to 120,000 steps (about 83 days at one-minute resolution). These are scenarios, not forecasts or exchange fill replays.

The pure simulation modules live in `src/simulation/`; Vue settings, charts and market fetching stay outside the accounting engine. Unit tests independently reconstruct the cash ledger and check both calendar exit modes, exact per-leg settlement times, frozen settlement payouts (including zero), live-option delta, ratio sizing, expiry/close fees, bounded spreads, zero-net-premium positions, variance integration, timers and attribution. The straddle API remains a thin preset over the position engine. `position-selection.js` isolates the shared builder’s display-date and instrument shapes from normalized simulation legs. Rendered-component tests exercise the actual shared builder, a call calendar, adding/removing legs, automatic reruns, charts, inspection, CSV export, validation, tabs and asset switching.

## Data and interpolation

- **Live marks is the default.** Fresh quotes arrive through a single batched Thalex `public/subscribe` request for the `lwt_options.<asset>USD.all.1000ms` bulk channel. Each refresh collects a snapshot and closes the socket; this is not a continuously updating subscription. REST `ticker` requests fill only names missing from the bulk snapshot, or the whole chain if WebSocket is unavailable. Stale marks (>120 seconds) and invalid tickers reported by the stream remain unavailable without a second REST request for the same mark. **Book mid / mark fallback** solves IV from the best bid/ask midpoint using the ticker forward, an undiscounted Black model and a 365.25-day year, falling back to the same option’s mark IV when its book is empty, crossed or outside model bounds. A missing book never removes a valid mark quote. Snapshot timestamps disclose sequential collection.
- Historical IV uses closing mark IV and exact matching index closes for the latest 2,000 completed hours. Up to 2,000 interpolated observations are retained per currently live expiry; recently listed expiries and gaps in the bundled history can leave fewer observations. API backfill fills the gap between the actual Parquet coverage and the latest completed hour, within the existing lookback; there is no fixed 48-hour cap.
- ATM follows the notebook: average call/put squared IV per strike, interpolate variance between strikes around that observation’s spot, then take the square root. Spot outside available strikes uses a flagged nearest-strike fallback.
- 10Δ/25Δ put/call slices interpolate same-side variance in Black–Scholes spot delta, using zero rates/carry and the observation’s time to expiry. Unbracketed wings are omitted. This is an explicit approximation to exchange forward delta.
- Expiries are equally spaced. Scatter jitter changes x only. Percentiles use each expiry’s available sample, with half-weight for ties. Live book-mid percentiles compare to historical **mark** IV, not historical executable books.

## Forward volatility and its history

Forward mode shows fixed adjacent listed-expiry intervals: **Now → first expiry**, then **first → second**, **second → third**, and so on. Labels, tooltips, details and PNG filenames identify the selected view. The first interval equals the first expiry’s IV. Each subsequent interval uses:

`forwardVol = sqrt((IV_far² * (expiry_far - timestamp) - IV_near² * (expiry_near - timestamp)) / (expiry_far - expiry_near))`

The calculation differences **total variance**, not IV levels. Live inputs share the current snapshot reference time. Every historical observation is recomputed using its own remaining maturities and requires both legs at the **same UTC hour**. A missing intermediate maturity never causes the chart to bridge to a different interval. Historical percentiles and counts are recalculated from forward-vol observations, rather than reusing expiry-IV ranks. Exactly zero forward variance is valid; negative increments are omitted and disclosed rather than clamped to zero.

Forward values are derived from the selected ATM/delta IV slice. For delta wings in particular these are smile-slice forward estimates, not model-free forward variance or a fitted arbitrage-free surface. A nearest-strike flag propagates if either input IV used that fallback.

The RV overlay compares each forward bucket with the **most recent history of the same duration**. A forward bucket T₁ → T₂ ahead uses the latest T₂ − T₁ hours of OHLC, rounded up to whole hours. For example, day 7 → day 30 uses the most recent 23 days. All lookbacks end at the same latest available completed hour, so they overlap. The first bucket uses the same RV as the first expiry-IV point. RV is computed directly from bars in each lookback, rather than subtracting cumulative RV estimates. Each window independently requires 99% hourly coverage. No additional API data is required beyond the index history already loaded for the longest maturity.

Reference for total-variance differencing: [QuantLib Black forward-volatility implementation](https://github.com/lballabio/QuantLib/blob/master/ql/termstructures/volatility/equityfx/blackvoltermstructure.cpp).

## Realized volatility

For each expiry, calculate its time to maturity at the current snapshot and round **up** to a whole number of hours. Apply that same number of hours backwards, ending at the latest available completed hourly index bar before the snapshot. Publication lag therefore shifts the window end back to the most recent available close, which is shown in RV tooltips.

The Garman–Klass variance contribution of each OHLC bar is:

`v = 0.5 * ln(high / low)^2 - (2 * ln(2) - 1) * ln(close / open)^2`

Annualized RV is `sqrt(mean(v) * 24 * 365.25)`. No demeaning is applied. This OHLC estimator assumes a continuous, zero-drift process and does not capture unobserved jumps between bars. Missing, nonpositive or internally inconsistent OHLC bars are skipped. With at least **99% valid hourly coverage**, RV is estimated as the mean variance of the available bars across the full requested window; missing bars are not zero-filled and the lookback start/end are not shortened. Below 99% coverage, RV remains unavailable. The detail table shows RV, coverage, IV minus RV in percentage points, and exact valid/expected bar counts in the RV tooltip. Small gaps are disclosed through coverage and tooltips without markers on the chart. This assumes the available bars are representative of the small missing portion; material gaps are not estimated.

The canonical files contain a missing 09:00 UTC index bar on 21 October 2026; the public API also returns no data for that hour. That single gap no longer hides the longer-maturity RV points: their coverage is above 99%, with actual coverage shown in the detail table.

[Garman and Klass, original paper](https://www.cmegroup.com/trading/fx/files/a_estimation_of_security_price.pdf)

## Parquet reuse and incremental fetching

`build-history.mjs` reads all index OHLC and recent **closing** IVs from the canonical backtest Parquet files. It creates content-hashed index and per-expiry JSON shards in ignored `public/history-cache/`, plus small versioned manifests. This avoids reusing the backtest’s opening-IV artifacts or leaking their pricing conventions into this app. Building the app packages these static cache files automatically.

Live quotes and history load in parallel. The browser publishes cached index/history as shards arrive, before waiting for the API differential. Live quotes update as ticker messages arrive (UI changes are coalesced over 50 ms); historical corrections publish after each expiry finishes so a partly fetched strike ladder does not distort new hourly points. The completed live snapshot and its warnings publish independently of the historical backfill. History activity reports each range as it starts and finishes; expiry progress advances after its checked inputs are published, so a busy expiry does not look idle while its chart stays unchanged. Historical interpolation is cached separately from live quotes. Chart redraws retain the historical dot cloud, with keyed joins for added hours; source tooltips are formatted only on hover and metadata updates do not redraw the plot. The expiry axis stays fixed while data fills in; cached history can render and export before any live quotes arrive.

The browser loads the asset’s index history and shards for its live expiries. It retains the full cached 2,000-hour scatter window and longer cached index history needed for RV. The build records separate **exclusive source-end timestamps** for index OHLC and option IV in the manifest, based on actual completed Parquet bars rather than build time. Index API backfill starts at its asset-wide source boundary. IV backfill uses each successfully decoded expiry shard’s own last completed bar, rather than assuming the asset-wide IV end covers every expiry. Both extend to the latest completed hour, even when the gap is longer than 48 hours. The adapter converts internal inclusive ranges to Thalex’s exclusive `to` boundary at the exact hour; subtracting one second would exclude the final candle and make IV lag the index inputs. Gaps inside the older Parquet history remain as supplied. New expiries with an absent, empty or failed shard have no Parquet IV coverage: they fetch from their instrument listing times, bounded by the 2,000-hour lookback. If a listing timestamp is missing, the lookback is the bound. Consequently, a newer asset-wide Parquet end cannot truncate an unarchived expiry’s available history. Cached data includes previously listed strikes for still-live expiries; fresh API supplementation uses currently listed instruments.

These per-expiry Parquet boundaries remain fixed while API additions accumulate in memory, so failed requests are still retried on refresh rather than skipped because a newer hour was fetched. Older manifests infer boundaries from the loaded bars. If a source cache is unavailable, the corresponding requested lookback bounds the API fallback (2,000 hours for scatter, or the longer required index window for RV).

For **ATM**, the request planner uses each historical hour’s index close to select the nearest strike below and above spot (one strike when spot matches exactly). It checks both call and put IVs so variance averaging is unchanged. Confirmed empty brackets widen to neighbouring strikes; request failures stop expansion for that expiry rather than being treated as proof of absent data. Required hours are combined into one request envelope within the backfill window per instrument per round, reusing extra returned hours. For **delta slices**, only the selected option side is supplemented across its strikes; narrowing delta strikes further would require assumptions about historical IV. Switching slice automatically backfills missing history using the existing chain and snapshot, without fetching live quotes again. The existing in-memory archive is shared across selections, so switching between put deltas reuses the same additions.

Known index gaps are skipped when selecting option hours because IV observations without matching index closes cannot be used. Index API pagination reaches its own Parquet boundary, independently of IV coverage. Longer RV lookbacks retain the existing coverage checks.

Successful additions are retained in memory per asset for the browser session. Content-hashed static shards use normal HTTP caching; manifests are revalidated on first load. Each refresh considers its current live expiries, loads newly requested shards and retries failed reads without reloading successfully decoded shards. Static retries preserve newer API observations. Failed manifest loads are also retryable while retaining the session archive. Empty API windows are remembered for one minute, allowing later retry after publication lag. Missing/invalid static cache files trigger a disclosed API fallback bounded by the requested lookback. No IndexedDB or localStorage history persistence is used; reloading the page discards session additions. Live quotes are always fetched afresh. The subtitle hover tooltip shows only the overall IV and RV data ranges and sources. REST supplementation uses the shared rate-limit policy below; the batched WebSocket snapshot avoids one REST request per listed option. A stream that stops adding names settles after 1.5 seconds (longer than its one-second notification interval); a stream with no usable data times out after eight seconds. Background historical corrections can still take time because their API remains per instrument, but the chart no longer waits for them.

## REST limits and local CORS handling

Term Structure and Skew use the same transport in `lib/thalex-rest.js` and `lib/thalex-rate-limit.js`. The exchange budget enforces ceilings of **100 request starts in a rolling second for the initial burst**, then **100 ms between starts (10/second)**. The public transport applies a stricter **250 ms spacing (4/second), without an initial burst**, because live checks received Cloudflare 1015 responses at both 10/s and 5/s. Fallback tickers, historical backfill, retries and WebSocket subscription requests all consume the same budget. Actual network dispatch occurs inside the budget lock. Timer delays and idle periods do not create a catch-up burst. Refresh/reload preserves spent burst credit, pacing and cooldown. A separate concurrency bound permits at most four in-flight REST requests. Identical in-flight requests within the same cancellation scope are deduplicated before entering the queue.

The bucket survives HMR in memory and full reloads in localStorage. Web Locks coordinate reads and writes between this app’s tabs on the same origin when supported. If storage/locks are unavailable, coordination is best effort within the tab. Other origins, apps using a different transport, and machines sharing the same public IP are outside this browser’s budget; rate-limit responses therefore still trigger adaptive backoff.

A 429 or rate-limit error inside an HTTP 200 JSON response pauses the entire shared queue for at least ten seconds, respects longer `Retry-After` values in seconds or HTTP-date form, adds jitter and drains the bucket. It also halves the shared sustained rate, down to a minimum of one request/second. When the pause ends, requests resume at that slower pace without another burst. After a quiet minute, the rate recovers gradually by one request/second per minute, up to the configured public pace of four. Both the pacing deadline and reduced rate survive refresh/reload. Transient HTTP errors have up to three retries; opaque CORS/network errors get only one retry and trigger the same conservative cooldown and slowdown. Five shared rate-limit/network failures in 30 seconds stop further network work for at least 30 seconds. Cancelled queued jobs do not fetch or consume tokens. Refresh preserves the existing chart if the provider is still cooling down.

For local development, requests use the same-origin **`/thalex-api`** Vite proxy (prefixed by `VITE_BASE_PATH` when set). Local Vite preview uses it too. The proxy forwards only to `https://thalex.com/api/v2/public`, preserving upstream status and `Retry-After`; it does not retry, bypass the rate limit, disable TLS validation or add an open CORS policy. This allows the client to handle upstream 429s which otherwise lack CORS headers. Restart the dev server after updating the proxy configuration. Leave `VITE_THALEX_API_BASE` unset to use this automatic local route; an explicit override takes precedence.

Deployed static sites still rely on Thalex’s CORS headers; a local Vite proxy is not a production backend. When a blocked response is opaque, the client cannot inspect its status or headers and conservatively backs off rather than repeatedly retrying it. A hosted production relay would need its own shared server-side IP budget.

Validation includes deterministic token/refill/cooldown tests and a local mock proxy returning 429 without CORS headers; it deliberately does not flood the public API to test its limit.

## Boundaries

- `scripts/build-history.mjs`: canonical Parquet to browser-cache conversion.
- `history-cache.js`: static cache contract, session archive and missing-hour ranges.
- `live-quotes.js`: batched WebSocket ticker contract, snapshot lifecycle and shared ticker normalization.
- `thalex-rate-limit.js`: re-exports shared token accounting, persisted budget, cancellation and cooldown from `lib/`.
- `thalex-rest.js`: re-exports shared REST request orchestration, retry policy and endpoint selection from `lib/`.
- `atm-history-plan.js`: per-hour ATM strike selection and outward search after empty responses.
- `market-data.js`: Parquet-to-present backfill, selected-side fetching, differential merge and progressive publishing.
- `volatility.js`: IV interpolation and percentiles.
- `forward-volatility.js`: adjacent-expiry forward variance and contemporaneous historical pairs.
- `realized-volatility.js`: OHLC estimator and matched windows.
- `App.vue`: loading and control orchestration.
- Chart components: rendering, settings and exports through the shared PNG helper.
